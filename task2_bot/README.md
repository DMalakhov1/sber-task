# Telegram-эксперт по электроэнергетике

Основной режим по условию: официальный API DeepSeek, модель `deepseek-flash`. Используется совместимый OpenAI Python SDK. Ключ пользователя запрашивается в личном чате; после проверки бот приветствует пользователя. Официальная настройка сверена 07.10.2026: https://api-docs.deepseek.com/.

## Запуск из корня проекта

```bash
python -m pip install -r task2_bot/requirements-semantic.txt
cp task2_bot/.env.example task2_bot/.env
```

В `.env` заполните только TELEGRAM_BOT_TOKEN новым токеном BotFather. Для DeepSeek оставьте:

```env
OPENAI_BASE_URL=https://api.deepseek.com
OPENAI_MODEL=deepseek-flash
```

В комплекте уже есть PDF и индекс. При необходимости заново подготовить их:

```bash
python -m task2_bot.rag.download fetch
python -m task2_bot.rag.build_index
```

Проверка файлов и запуск:

```bash
python -m task2_bot.bot.main --check
python -m task2_bot.bot.main
```

`--check` без сети проверяет `.env`, непустой Telegram-токен, модель/base URL, SHA-256 трёх PDF и целостность RAG-индекса (хеши, число фрагментов и размерность vectors). API-ключ пользователя и доступность модели он намеренно не проверяет: ключ вводится только в Telegram. Первый семантический поиск может скачать веса E5. В Telegram: `/start` → личный ключ DeepSeek → приветствие → вопрос. `/new` очищает только историю диалога и оставляет проверенный API-ключ активным; `/reset` удаляет и ключ, и историю. Остановка — Ctrl+C. Сессия хранится в памяти до перезапуска, /reset или 30 минут бездействия. Удаление сообщения с ключом не гарантирует удаления копий Telegram.

### Память диалога

Бот хранит только краткосрочную память текущей сессии в RAM: до 8 последних ходов, максимум 3 последних хода используются для разрешения ссылок и эллипсиса. Для успешных ответов память хранит не только вопрос, но и тексты уже валидированных claims и названия фактически процитированных отчётов; это позволяет понимать продолжения вроде «какая из этих стран?» или «а в этом отчёте?». Сами claims в новом ответе доказательством не считаются — факты всё равно заново подтверждаются PDF-фрагментами. В память попадают и корректные отказы `abstain/no_hits`, чтобы следующий вопрос не перескакивал на старую тему. История не является источником фактов: фактические утверждения всё равно должны заново подтверждаться найденными PDF-фрагментами. Для уже показанных источников бот сохраняет структурированные `title/page/url`, поэтому явные мета-вопросы вида «На какой странице был источник первого ответа?» или короткое «Где это написано?» отвечаются из валидированной памяти без повторного RAG-поиска. Если пользователь называет новый отчёт или новую предметную тему (например, «Где в Electricity 2025 написано про спрос в Индии?»), запрос обязательно идёт через retrieval и не подменяется источниками прошлого ответа. Ординалы «первого/второго/третьего ответа» считаются по всем сохранённым ходам, включая корректные отказы; для ответа без цитат бот прямо сообщает, что подтверждённых источников у него не было. `/reset`, TTL или перезапуск удаляют ключ и историю.

## Дополнительный провайдер

Для запуска используется официальный DeepSeek API: `OPENAI_BASE_URL=https://api.deepseek.com` и `OPENAI_MODEL=deepseek-flash`. API-ключ DeepSeek вводится пользователем в личном чате Telegram и хранится только в памяти сессии.

## Поиск и проверка ответа

Три полных PDF: СиПР (236 страниц), Electricity 2025 (200), Global Energy Review 2025 (43). В индекс включено 1136 фрагментов с URL и физическим номером PDF-страницы. E5-small + BM25 объединяются RRF; текущие веса 1 и 1.0. Фрагменты: 380 токенов, перекрытие 60. Контекст — до 6 фрагментов и 11000 символов. Таблицы извлекаются pypdf, сложная структура может теряться.

RAG_TRANSLATION=on одним API-вызовом подготавливает поисковый запрос: для обычного вопроса делает английский вариант, а для follow-up также превращает реплику в самостоятельный запрос с учётом последних 3 ходов. Например, после вопроса про мировой спрос фраза «Какие основные причины этого роста?» переписывается в самостоятельный запрос про причины роста мирового спроса. При ошибке подготовки используется локальный fallback. Цитаты проверяются на вхождение в найденный фрагмент; URL и страницы добавляет код.

RAG_VERIFY_CLAIMS=on (основной режим) добавляет отдельный запрос проверки утверждений по цитатам и контексту: числа, направления изменений, периоды, регионы, факт/прогноз. При отрицательном, некорректном или недоступном результате проверки ответ не показывается. Это дополнительная модельная проверка, не доказательство логического следования и не гарантия отсутствия ошибок.

Стоимость: обычно до 3 генеративных вызовов на русский вопрос (подготовка/перевод поискового запроса, ответ, проверка смысла), без подготовки — до 2. Подготовка запроса одновременно выполняет разрешение follow-up, поэтому отдельного дополнительного вызова на память нет. RAG_REPAIR_QUOTES=on разрешает ещё один запрос для исправления цитат; по умолчанию off. Автоматические повторы SDK выключены. `RAG_VERIFY_CLAIMS=off` отключает дополнительную проверку и уменьшает расход, сохраняя проверку цитат.

Ключи не включаются в промпты и телеметрию. Ошибки и ответы провайдера не логируются целиком. Результаты оценки и ограничения — VALIDATION.md; платные опыты требуют явного --allow-paid и ограничены --max-api-calls.


## Доработка поиска: экспериментальный reranker

Реализован локальный второй этап: исходный BM25/E5/RRF → до 24 кандидатов →
CrossEncoder → до 6 фрагментов → прежняя проверка цитат. URL, физические страницы
PDF и идентификаторы не меняются. Сохраняется разнообразие страниц и охват явно
названных отчётов. Оценка reranker не является вероятностью правильности ответа.

В `.env` можно включить:

```env
RAG_RERANK=on
RAG_RERANK_MODEL=cross-encoder/mmarco-mMiniLMv2-L12-H384-v1
RAG_RERANK_CANDIDATES=24
RAG_RERANK_DEVICE=cpu
RAG_VERIFY_CLAIMS=on
RAG_VERIFY_RELEVANCE=on
```

Установка использует существующий `requirements-semantic.txt`. Новая модель
скачивается при первом запросе и занимает дополнительную память. CPU выбран для
переносимости; на Mac можно отдельно проверить `RAG_RERANK_DEVICE=mps`.
CrossEncoder работает локально, не расходует токены API. Рост задержки нужно измерить.
Пары обрезаются моделью до 512 токенов: длинный фрагмент может потерять конец.

При ошибке модели, неверной форме или NaN/Inf в оценках используется **точно прежняя
выдача top-6**, а reranker отключается до перезапуска, чтобы не повторять неудачную
загрузку при каждом вопросе. В `outputs/metrics.local.jsonl` поле `rerank_status`
показывает `ok`, `fallback`, `off` или `no_hits`. Личный `/debug` при запуске с
`--debug` показывает ID, страницы и `rerank_score`, но не ключи и не тексты запросов.

`RAG_VERIFY_RELEVANCE=on` добавляет проверку соответствия вопросу: период, регион,
показатель, сравнение; исправление неверной предпосылки считается допустимым ответом.
При `RAG_VERIFY_CLAIMS=on` обе проверки выполняются **одним проверочным API-вызовом**.
Если проверка утверждений выключена, проверка соответствия сама требует одного
вызова. Дополнительных циклов повторной генерации нет. Отказ с причиной
`off_topic_answer` отличим от `unsupported_claim` и технической ошибки.

По умолчанию новые переключатели выключены: улучшение на независимых вопросах и
частота ложных отказов ещё не измерены. Текущий рабочий путь сохраняется.

### Сравнение без платного API

Из корня проекта, с активированным окружением:

```bash
python -m task2_bot.eval.rerank_comparison --mode hybrid --translation manual --output task2_bot/outputs/rerank_dev_run1.json
```

Отчёт содержит исходный top-6, охват top-24 и top-6 после reranker. Ошибка модели
останавливает сравнение, а не маскируется fallback. Файл результата не перезаписывается.
`manual` использует сохранённые переводы и не измеряет качество живого переводчика.
Для проверки без новой модели:

```bash
python -m task2_bot.eval.rerank_comparison --mode bm25 --translation manual --candidate-only --output task2_bot/outputs/candidates_run1.json
```

На dev зафиксировано: BM25 top-6 — 13/17 попаданий в нужную страницу; top-24 — 17/17.
Все требуемые группы страниц найдены соответственно в 10/17 и 15/17 вопросах.
Это диагностический потенциал набора кандидатов, **не результат reranker**.
Набор dev уже использовался для настройки; прежний test тоже просматривался.
Для окончательной оценки подготовьте новые вопросы с проверенными страницами.

### Живая оценка с ограничением расходов

После установки зависимостей можно явно запустить до 5 вопросов, максимум 15
генеративных вызовов. Ключ вводится скрыто в терминале, не в аргументах команды:

```bash
python -m task2_bot.eval.run_answers --allow-paid --max-questions 5 --max-api-calls 15 --rerank on --verify-claims on --verify-relevance on --output task2_bot/outputs/live_rerank_run1.jsonl
```

Проверьте ответы и цитаты вручную: правильность чисел, соответствие вопросу, ложные
отказы, время и usage. Одинаковые вопросы сравнивайте с `--rerank off` в отдельном
файле, учитывая дополнительный расход второго запуска. В этой доработке платные
запросы не выполнялись.

### Минимальный диагностический режим

Установите `task2_bot/requirements.txt`, используйте готовый индекс и настройки:

```env
RAG_SEARCH_MODE=bm25
RAG_TRANSLATION=off
RAG_RERANK=off
RAG_VERIFY_CLAIMS=off
RAG_VERIFY_RELEVANCE=off
```

Затем `python -m task2_bot.bot.main --allow-lexical`. Этот режим не загружает E5 или
CrossEncoder; генерация по-прежнему требует ключ. Проверка дословных цитат остаётся.
Русские вопросы к английским документам могут находиться хуже; для диагностики
задавайте английские вопросы к IEA. Это не основной режим для оценки межъязыкового RAG.

## Источники идей

Архитектурные решения сверялись с открытыми RAG-проектами; код из них не копировался.
Полезные идеи, которые совпадают с текущей реализацией или были адаптированы под небольшой корпус:

- `Pavlo-2201/rag-document-assistant`: широкий candidate pool → cross-encoder → короткий top-k, строгий отказ и проверяемые ссылки; у нас это реализовано опциональным локальным reranker и неизменяемой provenance-метаинформацией.
- `ThinkCode/RAG-Documents` (fork kotaemon): hybrid retrieval, reranking, relevance guard и работа со сложными follow-up; из этого взяты идеи раздельной проверки relevance/faithfulness и явного query rewriting для диалога. Полный агентный/decomposition-стек сознательно не переносился как избыточный для трёх фиксированных PDF.
- `KitaOg/rag-document-search`: простое разделение loader/chunker/retriever/generator/pipeline и возврат sources; текущий проект уже имеет более строгую версию этой структуры. FastAPI/загрузка произвольных документов не нужны по условию задания.

Дополнительно: `https://github.com/000p1umDiesel/rag_economic` и
`https://github.com/marinamardoyan/RAG-RAIF`.
Модель reranker: https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1
Документация CrossEncoder: https://sbert.net/docs/package_reference/cross_encoder/cross_encoder.html

## Тон ответов (08.10.2026)

Бот обращается на «ты», начинает с краткого ответа и поясняет сложные термины.
Приветствие: «Привет! Я помогу разобраться в электроэнергетике по отчётам IEA и СиПР.
Задай вопрос — отвечу по документам и покажу источники со страницами».
При нехватке подтверждения просит уточнить период, регион или отчёт. Ошибка API,
лимит и таймаут обозначаются отдельно: они не означают отсутствия сведений в PDF.
Формулировки ошибок используют фиксированные шаблоны, без текста исключений и ключей.

Стиль задан системным промптом и сообщениями интерфейса; отдельного вызова модели
для переписывания ответа нет. Проверка цитат, смысловая проверка, соответствие
вопросу, reranker и диагностические команды сохранены. `RAG_RERANK` и
`RAG_VERIFY_RELEVANCE` остаются опциональными. Тесты подключения — офлайн;
модель reranker в новой среде не загружалась, платный API не вызывался.

Перед сдачей проверь в личном Telegram-чате: обычный вопрос → уточнение
«А в 2025 году?» → вопрос с неверной предпосылкой → вопрос вне документов.
Для воспроизводимой оценки используй eval-скрипты по инструкции выше с явно
ограниченным числом вопросов и своим ключом. Моковые ответы из тестов не являются
измерением естественности реального ответа DeepSeek.
