# Задача 1: прогноз Brent

Реализован офлайн-конвейер на неизменённом срезе пользователя до марта 2026.
Это прогноз от исторического среза, а не от текущей даты. Дата первоначального
скачивания неизвестна; полнота марта независимо не подтверждена.

## Запуск из корня с общим .venv
```bash
python -m pip install -r task1_brent/requirements.txt
python -m task1_brent.run
python -m pytest -q tests/test_brent.py
```
Расчёт всех горизонтов на CPU занимает несколько минут. Лимит численных потоков
внутри конвейера — 1 для воспроизводимости и чтобы не перегружать ноутбук.
Интернет и платные API не используются. Результаты перезаписываются в outputs/.
Прямые зависимости зафиксированы; полный список Linux-окружения — docs/validation_environment.txt.
Mac отдельно не проверен. Общая инструкция запуска — корневой README.md.

## Методы
- Naive: последнее значение; drift: средний прирост на доступном train.
- ETS: затухающий тренд лог-цены, без сезонности.
- Ridge и HGB: отдельная регрессия лог-цены для каждого горизонта 1–21.
  Признаки: текущая и прошлые цены, прошлые средние, изменения, волатильность.
  Scaler обучается только на train; цель каждой пары не позже даты выпуска.
- Mean reversion: возврат лог-цены к среднему последних 120 месяцев,
  период полураспада 12 месяцев. Это фиксированное сценарное допущение.
- Ensemble: равные веса naive, ETS, Ridge и mean reversion. Веса не подгоняются.

Методы используют один ряд, но различаются моделью динамики и способом обучения.
Регрессии на лагах тоже имеют авторегрессионную структуру — наличие ML само по себе
не означает использования внешних факторов. Макровариант Ridge оценивается отдельно,
если локально есть таблица диплома; в финальный прогноз и выбор модели он не входит.
Сдвиг макропоказателей на месяц — непроверенное допущение о доступности.
Если макрофайла нет в клоне Git, основной конвейер продолжает работать.

## Протокол и результаты
- Статистические модели: расширяющееся окно, минимум 120 наблюдений.
- Прямые модели оцениваются с января 2017; train включает всю доступную историю.
- Для каждого горизонта основная таблица сравнивает одинаковые даты выпуска.
- Development: target до января 2022. Validation: origin с января 2022.
  Пересекающие границу цели не попадают в development.
- Выбор по MAE development сохраняется в selection_development.csv.
- Последние годы ранее просматривались в Kimi, поэтому validation — ретроспективная
  проверка, не полностью нетронутый тест. Выбор не перенастраивается по validation.
- Интервалы: по модулю лог-ошибки, отдельная калибровка каждого из 21 горизонта.
  При проверке используются только цели, известные ДО начала validation.
  Финальная калибровка использует известные ошибки до мартовского среза.
- Измеряются покрытие, ширина, pinball обеих границ и interval score.
  Номинальные 90% не гарантируются при смене режима; искусственного пола цены нет.

Таблицы и выводы автоматически собираются в outputs/RESULTS.md.
forecast_2026-04_2027-12.csv содержит все семь моделей с границами;
selected_forecast.csv — модель, выбранную на development для каждого горизонта.
График показывает сравнение всех моделей и интервал ансамбля, не объявляет его победителем.
Данные после марта не загружались; сравнение с фактом апреля–сентября не выполнено.
Три месяца 2026 года позволяют описать аномалию, но не доказать структурный сдвиг.

## Происхождение реализации
Основа data/models/backtest/run и исходных 11 тестов — предоставленный пользователем
архив Kimi. В проекте изменены лог-цель ML, интервалы, калибровка по target,
набор горизонтов, дополнительные методы, оценка, отчёт и тесты.
Старые численные результаты Kimi не включены как результаты новой версии.

Бэктест использует сохранённые значения ряда, а не архивные публикации каждой даты (vintages). Поэтому влияние позднейших пересмотров данных отдельно не оценивалось.
